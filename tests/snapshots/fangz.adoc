[abstract]
--
Fangz Forge is a realistic sample application used to exercise a full command tree. It models project setup, release workflows, configuration, and runtime inspection.
--

[#cmd-fangz]
== Synopsis

[source,sh]
----
fangz [OPTIONS] <COMMAND>
----

.Create a service project with verbose output.
====
[source,sh]
----
fangz --verbose project init api --template service
----
====

.Deploy two artifacts using a canary rollout.
====
[source,sh]
----
fangz deploy production api.tar worker.tar --strategy canary --parallelism 2
----
====

== Global options

=== `-v, --verbose`

Print detailed progress information.

Enable verbose progress messages for every command in the selected command path.

*Default:* `false`

*Scope:* `local`

.Show deployment progress.
====
[source,sh]
----
fangz --verbose deploy staging
----
====

=== `--color <VALUE>`

Control terminal color output.

Choose automatic color detection, force color, or disable color entirely.

*Default:* `auto`

*Possible values:* `auto`, `always`, `never`

*Scope:* `local`

=== `-c, --config <PATH>`

Load configuration from a specific file.

Override the default project configuration discovery path.

*Scope:* `local`

=== `-l, --label <NAME>...`

Attach a repeatable label to the operation.

Labels are free-form and are forwarded to project and deployment integrations.

*Scope:* `local`

=== `-D, --define <KEY=VALUE>...`

Set a free-form build definition.

Each definition must use KEY=VALUE syntax. Definitions are not restricted to a fixed key set.

*Scope:* `local`

=== `-h, --help`

Print help.

*Scope:* `built-in`

=== `-V, --version`

Print version.

*Scope:* `built-in`

[#cmd-fangz-deploy]
=== `fangz deploy`

Deploy one or more project artifacts.

Deploy uses an explicit environment, rollout strategy, and optional runtime settings.

Parent: xref:cmd-fangz[`fangz`]

==== Synopsis

[source,sh]
----
fangz deploy [OPTIONS] <environment> <artifacts>...
----

==== Arguments
===== `<environment>`

Target environment.

*Required* when present in the synopsis.

*Possible values:* `development`, `staging`, `production`
===== `<artifacts>...`

Artifact files to deploy.

*Variadic:* accepts multiple values.

==== Options
===== `-v, --verbose`

Print detailed progress information.

Enable verbose progress messages for every command in the selected command path.

*Default:* `false`

*Scope:* `global`

.Show deployment progress.
====
[source,sh]
----
fangz --verbose deploy staging
----
====
===== `--color <VALUE>`

Control terminal color output.

Choose automatic color detection, force color, or disable color entirely.

*Default:* `auto`

*Possible values:* `auto`, `always`, `never`

*Scope:* `global`
===== `-c, --config <PATH>`

Load configuration from a specific file.

Override the default project configuration discovery path.

*Scope:* `global`
===== `-l, --label <NAME>...`

Attach a repeatable label to the operation.

Labels are free-form and are forwarded to project and deployment integrations.

*Scope:* `global`
===== `-D, --define <KEY=VALUE>...`

Set a free-form build definition.

Each definition must use KEY=VALUE syntax. Definitions are not restricted to a fixed key set.

*Scope:* `global`
===== `-s, --strategy <VALUE>`

Rollout strategy.

Canary and blue-green deployments introduce additional validation before traffic is switched.

*Default:* `rolling`

*Possible values:* `rolling`, `canary`, `blue_green`

*Scope:* `local`
===== `-p, --parallelism <COUNT>`

Maximum concurrent deployment workers.

*Default:* `1`

*Scope:* `local`
===== `--timeout <SECONDS>`

Per-artifact timeout in seconds.

*Default:* `30`

*Scope:* `local`
===== `-r, --region <REGION>`

Optional deployment region.

*Possible values:* `us-east`, `us-west`, `eu-central`, `ap-southeast`

*Scope:* `local`
===== `--[no-]wait`

Wait for the rollout to become healthy.

*Default:* `true`

*Scope:* `local`
===== `--dry-run`

Plan the rollout without applying it.

*Scope:* `local`
===== `--force`

Apply despite an existing active rollout.

*Scope:* `local`
===== `-E, --variable <SETTING=STATE>...`

Set a constrained deployment variable.

Variables are validated before the deployment hook executes.

====== Severity levels

[cols="1,4"]
|===
| Level | Meaning

| `enabled`
| Enable the setting.

| `disabled`
| Disable the setting.

|===

====== Rules and defaults

[cols="2,1,5"]
|===
| Rule | Default | Description

| `feature`
| `disabled`
| Toggle a named feature for this deployment.

| `telemetry`
| `enabled`
| Enable or disable telemetry collection.

| `maintenance`
| `disabled`
| Put the service in maintenance mode during rollout.

|===

====== Override behavior

Repeat a key to override an earlier value; the final occurrence wins.

*Scope:* `local`

.Disable telemetry for a canary deployment.
====
[source,sh]
----
fangz deploy staging --variable telemetry=disabled --strategy canary
----
====
